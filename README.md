# termsnap

Рабочее название. Запуск команд и разбор их вывода с ANSI-цветами в нейтральную модель: строки, фрагменты, стили.
Модель не привязана к способу показа (Word, SVG, PNG) и к способу запуска (каналы, псевдотерминал).

Готово:

- запуск через каналы (`PipeBackend`, только стандартная библиотека);
- запуск в псевдотерминале (`PtyBackend`, `termsnap[pty]`): ConPTY в Windows, `pty` в Linux и macOS, экран ведет `pyte`;
  программам можно печатать строки (REPL, IPython);
- разбор SGR (16, 256 и 24-битные цвета, жирный, курсив и другие), возврат каретки и стирание строки;
- темы для перевода цветов палитры в RGB;
- рисование в PNG (`termsnap[png]`, Pillow) шрифтами, установленными в системе.

```python
from termsnap import DARK, run

capture = run(["node", "app.js"])
for line in capture.lines:
    for span in line.spans:
        foreground, background = DARK.colors_of(span.style)
        print(span.text, foreground.hex, background.hex)
```

## Псевдотерминал

Некоторым программам нужен настоящий терминал: `rich` и IPython в Windows при выводе в канал печатают без стилей,
`top` и подобные рисуют экран абсолютными позициями курсора, а длинный вывод уходит за границу экрана.

```python
from termsnap import PtyBackend, run

capture = run(["python", "app.py"], backend=PtyBackend(), columns=100, rows=30)
```

Программа видит терминал заданного размера (`isatty()` истинно, `COLORTERM=truecolor`), стандартный вывод и вывод
ошибок общие. Вывод читается как поток терминала, экран эмулирует `pyte` (`termsnap.screen`): строки, ушедшие за
верхнюю границу, сохраняются, длинные строки переносятся по ширине терминала, как в настоящем. Размер терминала
остается в `Capture.columns` и `Capture.rows`.

### Интерактивные программы

Программе можно напечатать строки (REPL, мастера установки):

```python
capture = run(
    ["uvx", "ipython"],
    backend=PtyBackend(),
    input=["squares = [n ** 2 for n in range(6)]", "squares", "1 / 0", "exit"],
    prompt=r"In \[\d+\]:$",
)
```

Каждая строка печатается с Enter, когда вывод молчит не меньше `settle` секунд (по умолчанию 0,5) и на экране виден
`prompt` - регулярное выражение, которое ищется в последней непустой строке без хвостовых пробелов (приглашение
без введенного текста). Без `prompt` ждется только тишина и хоть какой-то ответ на прошлую строку, что хуже для
программ, которые подолгу молчат (запуск, медленная команда). Последней строкой нужен выход (`exit`): если программа
не завершилась сама, будет `RunTimeout`. На картинке остается вся сессия, включая эхо введенного. Через каналы
(`PipeBackend`) ввод не работает, это `ValueError`.

Первый шаг тоже ждет вывода программы (пока она запускается, ввод может пропасть, например после `tty.setcbreak`);
молчащей с самого начала программе первый шаг уходит через секунду. В Linux и macOS терминал сам отвечает на
запросы программы (позиция курсора `ESC[6n`, тип терминала `ESC[c`), иначе `prompt_toolkit` (IPython) пишет, что
терминал не поддерживает запрос позиции курсора; в Windows это делает ConPTY.

### Клавиши и паузы

Кроме строк, в `input` можно класть клавиши и паузы (`termsnap.steps`):

```python
from termsnap import Key, Keys, Pause

run(
    ["uvx", "ipython"],
    backend=PtyBackend(),
    input=["6 * 7", Key.UP, Key.ENTER, Pause(1), "exit"],  # стрелка вверх достает прошлую строку
)
```

- `"текст"` печатается с Enter; `Keys("текст")` - как есть, без Enter (часть строки, управляющая последовательность);
- `Key.ENTER`, `TAB`, `ESC`, `BACKSPACE`, `DELETE`, `UP`, `DOWN`, `LEFT`, `RIGHT`, `HOME`, `END`, `PAGE_UP`,
  `PAGE_DOWN`, `CTRL_C`, `CTRL_D`, `Key.F[1]`...`Key.F[12]`, `Key.ctrl("l")`;
- `Pause(секунды)` ждет заданное время; после паузы все равно выдерживается `settle`.

После строки ждется ответ программы и (если задан `prompt`) приглашение; после клавиши и паузы - только `settle`,
потому что у клавиши ответа может не быть, а в середине строки приглашение уже не «чистое». Программам, которые
перерисовывают экран постоянно и никогда не молчат (htop, top), нужен `settle=0` и паузы между шагами.

### Когда снимать экран у долгой программы

`htop`, `top` и подобные сами не завершаются: без подсказки экран был бы доступен только при `RunTimeout`. Момент
снимка задает `Snapshot`:

```python
from termsnap import Snapshot

capture = run(["htop"], backend=PtyBackend(), snapshot=Snapshot(when="Tasks:", after=2))
assert capture.stopped  # программу остановили мы; returncode ничего не значит, а capture.ok истинно
```

Экран снимается, когда выполнены все условия: `input` напечатан, регулярное выражение `when` нашлось в тексте экрана,
прошло `after` секунд с последнего из этих событий (с запуска, если шагов и `when` нет). После снимка программа
останавливается. Не дождались - `RunTimeout` по общему `timeout` с тем, что успело появиться. Программа успела
завершиться сама до снимка - обычный результат, `stopped` ложно. `when` лучше, чем время, когда программа готовится
непредсказуемо долго (первое автодополнение IPython подгружает `jedi` несколько секунд).

## PNG

```python
from pathlib import Path

from termsnap import LIGHT, run
from termsnap.png import render_png

capture = run(["node", "app.js"])
Path("out.png").write_bytes(render_png(capture.lines, theme=LIGHT, font_size=14))
```

Шрифты в пакет не вшиваются. Семейство ищется среди установленных (`termsnap.png.find_family`), по умолчанию
берется первое подходящее из `DEFAULT_FAMILIES`, в котором есть все символы текста (так отсеиваются шрифты без
кириллицы). Источники сведений о шрифтах:

| Платформа | Основной источник | Запасной |
|---|---|---|
| Windows | реестр (`HKLM` и `HKCU`, `...\CurrentVersion\Fonts`) | обход `%WINDIR%\Fonts` и пользовательского каталога |
| Linux и прочие Unix | fontconfig (`fc-list`) | обход каталогов `XDG_DATA_DIRS` и `~/.fonts` |
| macOS | обход `/System/Library/Fonts`, `/Library/Fonts`, `~/Library/Fonts` | - |

Имена семейства и начертания читаются из самих файлов. Нужного жирного начертания нет (например, у вариативных
шрифтов вроде Cascadia Mono) - жирность имитируется, отсутствующий курсив заменяется прямым начертанием. Свой шрифт
задается файлами: `termsnap.png.from_files("MyMono-Regular.ttf", bold="MyMono-Bold.ttf")`.

### Внешний вид: тема, шрифт, поля

Все три настройки задаются при вызове `render_png` / `render_image` и ничего не меняют в самом захвате (`run`), поэтому
одну и ту же запись можно нарисовать по-разному. Той же темой (`theme.colors_of(span.style)`) можно перевести
цвета в RGB для вывода не в PNG, например в текст документа.

```python
from termsnap import DARK, run
from termsnap.png import render_png

capture = run(["node", "app.js"])
png = render_png(
    capture.lines,
    theme=DARK.derive(background="#0b1020", ansi={"red": "#ff757f", "bright_red": "#ff9aa2"}),
    fonts=["Fira Code", "Cascadia Mono"],
    padding=4,
)
```

**Тема** (`theme=`). Принимается `Theme`, имя из `THEMES` (`"dark"`, `"light"`) или словарь; `termsnap.get_theme`
приводит любой из способов к `Theme`, так что код, который только передает тему дальше, может не разбираться, что
именно ему дали (`ThemeSpec`).

- `DARK.derive(foreground=..., background=..., ansi={...})` - копия с другими цветами; меняется только указанное.
  Цвета пишутся как `"#rrggbb"`, `"#rgb"`, `(r, g, b)` или `Rgb`. Базовые цвета в `ansi` задаются номером 0-15 или
  именем (`black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `white` и `bright_*`; `ANSI_NAMES`), либо
  списком из всех 16.
- `Theme.from_mapping({...})` - то же из словаря (подходит для TOML и JSON): ключи `base` (от какой темы
  отталкиваться, по умолчанию `dark`), `name`, `foreground`, `background`, `ansi`. Опечатка в ключе - ошибка.
- `register_theme("my", theme)` - сделать тему доступной по имени (`theme="my"`).
- Цвета палитры 16-255 одинаковы во всех темах (куб и серые ступени xterm), переопределяются только базовые 16 и
  цвета по умолчанию.

```toml
[theme]
base = "light"
background = "#fafafa"

[theme.ansi]
red = "#c0392b"
```

**Шрифт** (`fonts=`). Принимается готовый `FontSet` (`find_family`, `from_files`), имя семейства или список семейств
в порядке предпочтения. Берется первое установленное семейство, в котором есть все нужные символы; если ни в одном
нет всех (в тексте эмодзи, иероглифы), берется то, где их больше. Названного семейства нет в системе - `FontNotFound`
с причиной по каждому, молча подставлять шрифт по умолчанию нельзя. Нужен запасной вариант - допишите
`*DEFAULT_FAMILIES` в конец списка.

Переопределяется только основной шрифт. Символы, которых в нем нет (эмодзи, стрелки, иероглифы), по-прежнему
подбираются автоматически из `FALLBACK_FAMILIES`, а рамки, блоки и шейды рисует сама библиотека, поэтому линии
таблиц не рвутся в любом шрифте.

**Поля** (`padding=`). Поля картинки со всех четырех сторон в пикселях «как на экране» (по умолчанию 16, умножаются на
`scale`). Можно уменьшить (`padding=4`) или убрать совсем (`padding=0`): фон ячеек тогда доходит до края картинки.
Отрицательное значение - ошибка. Раздельных полей по сторонам нет.

## Проверки и CI

Вся логика проверок живет в одном скрипте `ci/run.py` (стандартная библиотека; нужен только `uv`). GitHub Actions,
Docker и вы сами запускают одно и то же, поэтому проект не привязан к одному сервису:

```bash
python ci/run.py all          # стиль (ruff), типы (basedpyright), тесты (pytest); итог по каждому шагу в конце
python ci/run.py lint         # только стиль
python ci/run.py test -- -k pty -x
python ci/run.py --python 3.13 all    # другая версия Python, отдельное окружение .venv-ci-3.13
```

Тесты рисования и поиска шрифтов пропускаются, если в системе нет подходящего моноширинного шрифта с кириллицей;
тесты IPython - если нет `uvx` или сети; тесты `top` и `htop` - если этих программ нет.

### Linux без GitHub: Docker или Podman

```bash
python ci/run.py docker 3.13 3.14         # образ ci/Dockerfile для каждой версии и ``all`` внутри
python ci/run.py docker --engine podman
```

Это Linux-проверка на любой машине, в том числе из Windows и macOS. Зависимости лежат в отдельном слое образа и не
скачиваются заново, пока не менялись `pyproject.toml` и `uv.lock`. Пакеты ОС (шрифт для PNG, `htop`) ставит
`python ci/run.py system-deps`, тот же скрипт вызывается и в CI, и при сборке образа. В образе нет `git`, поэтому
пример с `git log` там не выполняется.

### GitHub Actions и act

`.github/workflows/ci.yml` - только обертка над `ci/run.py`: задача `linux` (Python 3.13 и 3.14) идет на каждый push и
pull request, задача `desktop` (Windows и macOS) - только после слияния в `main` и по кнопке. Действия закреплены
по коммиту. Linux-задачу можно прогнать локально через [act](https://github.com/nektos/act) (нужен Docker; образ
задан в `.actrc`):

```bash
act -j linux                               # обе версии Python
act -j linux --matrix python:3.14          # одна
```

`act` умеет только Linux-контейнеры, Windows и macOS локально им не запустить. macOS вообще нельзя проверить без
настоящего Mac (или облака), так что эта проверка есть только в задаче `desktop`.

### Другой CI

Не проверялось, но задумано так. Forgejo и Gitea Actions по описанию читают формат GitHub Actions (возможно, придется
поправить адреса действий `uses:`). Для GitLab CI, Woodpecker и подобных нужна короткая задача: образ с `uv`
(например, `ghcr.io/astral-sh/uv:python3.14-bookworm-slim`), затем `python ci/run.py system-deps` и
`python ci/run.py all`: логика проверок от CI не зависит.
