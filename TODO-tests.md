## 1. Уровни тестов: unit / integration / external

Решение: три уровня, маркеры pytest, быстрый прогон по умолчанию.

- unit: функции, модули, механизмы без запуска программ в оболочке (время и вывод задаются вручную)
- integration: настоящие процессы (PTY, канал), более сложные сценарии, демо и пробы, написанные в самом проекте
- external: чужие команды (`top`, `htop`, IPython, `git`, `ruff`, `pytest`) - обязательные, но с зафиксированными
  версиями и без сети; сюда же добавить пару тестов на нажатия клавиш (сейчас они только в сессиях IPython)

- [ ] Объявить маркеры в `pyproject.toml` (`--strict-markers`), расставить по файлам или каталогам
  (`tests/unit/`, `tests/integration/`, `tests/external/`)
- [ ] Команды в `ci/run.py`: `test --level unit|integration|external`, по умолчанию все
- [ ] Время выполнения каждого уровня записать в README (сейчас весь набор: Windows 84 с, Linux 108 с, macOS 122 с)
- [ ] Живые тесты с часами и допусками (`2 <= tick <= 8`, `duration < 10` в `test_interactive.py`) либо убрать

## 4. External: обязательные, с зафиксированными версиями, без сети

Вопрос: хватит ли в CI просто прописать версию IPython? Нет: `uvx ipython==X` все равно ходит в сеть при первом запуске.
Предложение: IPython, rich, ruff, pytest как зависимости группы `external` в `pyproject.toml` (версии держит `uv.lock`),
запуск через `uv run`, на CI они ставятся шагом `uv sync`, во время тестов сети нет.

- [ ] Группа зависимостей `external` и запуск IPython из окружения проекта вместо `uvx`
- [ ] Версии в ожиданиях (`"In [5]: exit"`) привязаны к зафиксированной версии IPython; в README записано, как обновлять
- [ ] `top` и `htop` на CI: Linux (procps, htop), macOS (`top` есть, `htop` через brew или явно не нужен), Windows (нет - явно)
- [ ] Таблица "что на какой ОС запускается" в README и в коде (одно место, а не россыпь `available`/`posix_only`/`skipif`)
- [ ] Пара тестов на нажатия клавиш (стрелки, Ctrl+C, Tab, Esc) вне IPython: на маленькой программе с `termios`/raw режимом
- [ ] Вложенные инструменты (`pytest_failure`, `ruff_diagnostics`, `git_log`): либо external с версией, либо заменить
  программой, печатающей заранее известный вывод
